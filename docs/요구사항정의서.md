# 요구사항 정의서

## 1. 프로젝트 개요

| 항목 | 내용 |
|---|---|
| 프로젝트명 | 머니로그 (MoneyLog) |
| 목적 | 개인 사용자가 수입/지출을 기록하고, 카테고리별·월별 통계로 소비 패턴을 파악할 수 있는 개인 가계부 서비스 |
| 대상 사용자 | 자신의 수입/지출을 기록하고 소비 습관을 확인하고 싶은 개인 사용자 |
| 구성 | 백엔드(Spring Boot REST API) + 프론트엔드(Next.js) |

## 2. 용어 정의

| 용어 | 설명 |
|---|---|
| 거래내역(MoneyLog) | 사용자가 등록한 수입 또는 지출 1건. 제목/설명/금액/날짜/카테고리/유형으로 구성 |
| 카테고리(Category) | 거래를 분류하는 항목(식비, 교통, 급여 등). 시스템에 고정된 18종 중에서 관리자가 활성화/비활성화 |
| 유형(Type) | 거래가 수입(INCOME)인지 지출(EXPENSE)인지 구분. 카테고리와 독립적으로 사용자가 직접 선택 (예: "투자" 카테고리로 이익도, 손실도 기록 가능) |
| 잔액(Balance) | 특정 월의 총수입 − 총지출 |

## 3. 기능 요구사항

각 항목은 **상태**를 함께 표기한다. ✅ 완료 / 🟡 부분 구현 / ❌ 미구현

### 3.1 인증 (✅)
- 이메일/비밀번호로 회원가입·로그인할 수 있다. 비밀번호는 BCrypt로 해시하여 저장한다.
- Google OAuth2로 로그인/가입할 수 있다.
- 로그인 성공 시 단기 Access Token(JWT, 15분)과 장기 Refresh Token(14일, httpOnly 쿠키)을 발급한다.
- Access Token 만료 시 Refresh Token으로 재발급받을 수 있으며, 재발급 시 Refresh Token도 함께 회전(rotation)한다.
- 이미 사용된(회전된) Refresh Token 재사용은 거부된다.
- 로그아웃 시 Refresh Token을 무효화한다.

### 3.2 카테고리 (✅)
- 서버 최초 구동 시 18종의 고정 카테고리(지출 12종, 수입 6종)를 시드 데이터로 생성한다.
- 모든 사용자는 활성화된 카테고리 목록을 조회할 수 있다.
- 관리자(ROLE_ADMIN)는 카테고리를 추가/삭제할 수 있다. (카테고리 이름 자체는 고정된 18종 중에서만 선택 가능)

### 3.3 거래내역 (✅)
- 로그인한 사용자는 자신의 거래내역을 등록/조회/수정/삭제할 수 있다(CRUD).
- 등록 시 제목, 설명, 금액(양수), 날짜, 카테고리, 유형(수입/지출)을 입력한다.
- 유형은 카테고리와 무관하게 독립적으로 선택한다.

### 3.4 조회 (✅)
- 거래내역 목록은 연도, 월, 유형(수입/지출), 카테고리로 필터링할 수 있다.
- 목록은 페이지 단위로 조회되며 기본 정렬은 최신순이다.

### 3.5 통계 (✅)
- 특정 월의 총수입, 총지출, 잔액을 조회할 수 있다.
- 특정 월의 카테고리별 지출 합계를 조회할 수 있다.
- 프론트엔드는 최근 N개월 수입/지출 추이를 여러 월의 통계를 조합해 보여준다.

### 3.6 인가 (✅)
- 모든 거래내역 접근은 로그인한 사용자 본인의 데이터로 제한된다.
- 카테고리 추가/삭제는 ROLE_ADMIN 권한이 있는 사용자만 가능하다.

### 3.7 화면 (✅)
- 랜딩 페이지: 서비스 소개
- 로그인/회원가입 페이지: 이메일 로그인 + Google OAuth 로그인
- 대시보드: 이번 달 요약(수입/지출/잔액), 카테고리별 지출, 월별 추이, 최근 거래내역
- 거래내역 페이지: 필터 + 페이징 목록, 등록/수정/삭제
- 통계 페이지: 대시보드보다 넓은 통계 화면(12개월 추이)
- 카테고리 페이지: 카테고리 목록, 관리자 전용 추가/삭제

### 3.8 문서 (✅)
- springdoc-openapi 기반 Swagger UI로 API 문서를 자동 생성한다.

### 3.9 배포 (❌ 미구현)
- Docker/docker-compose, GitHub Actions CI/CD, AWS EC2 배포는 아직 진행하지 않았다. (다음 우선순위)

## 4. 비기능 요구사항

| 구분 | 내용 |
|---|---|
| 보안 | 비밀번호 BCrypt 해시, Refresh Token은 SHA-256 해시로 저장(원문 미보관), Access Token은 프론트 메모리에만 보관(localStorage 미사용) |
| 인가 | 리소스 접근 시 항상 로그인 사용자 기준으로 필터링, 관리자 전용 기능은 JWT roles 클레임으로 판별 |
| 유효성 검증 | 모든 입력 DTO에 Bean Validation 적용 (필수값, 금액 양수, 이메일 형식 등) |
| 에러 응답 | 커스텀 예외 + `GlobalExceptionHandler`로 일관된 4xx 응답 (`{"message": "..."}` 또는 필드별 검증 오류) |
| 데이터베이스 | 로컬 개발은 H2(테스트) / MySQL 8(운영), JPA로 스키마 관리 |

| 화면 | 경로 | 비고 |
|---|---|---|
| 랜딩 | `/` | 비로그인 사용자 대상 |
| 로그인/회원가입 | `/login` | 탭 전환형, Google OAuth 버튼 포함 |
| 대시보드 | `/dashboard` | 로그인 필요 |
| 거래내역 | `/dashboard/transactions` | 로그인 필요 |
| 통계 | `/dashboard/stats` | 로그인 필요 |
| 카테고리 | `/dashboard/categories` | 로그인 필요, 관리 기능은 관리자만 |
